## Scope

Short design summaries in `docs/design/<area>.md`, one work file per approved task in
`docs/work/<id>.md`, and the convention in the [work-file README](README.md). Finished Tech work
is backfilled at feature granularity.

## Criteria

- Each design area has a summary that links its topic docs and an index table of ID, title and
  link, with no status column.
- Each work file has the convention's front matter and the Scope, Criteria, Decisions and Outcome
  sections.
- The README Docs list links the design and work indexes.
- Nothing under `docs/` is served or deployed.

## Decisions

- The owned topic docs stay where they are and remain the detailed reference.
- Live progress stays in the protocol state root; a work file records only milestones.
- Art and Gameplay write their own area summaries and work-file bodies.
- Backfilled items carry the date of their first implementing commit and the `backfill` marker as
  their approval reference.

## Outcome

docs/design holds ten area summaries and docs/work one file per approved task, with Tech items
backfilled (5a780e49), IDs allocated on main for Gameplay and Art (113f1404, 1abc0453) and their
bodies written by each role (eac6489a, 603f2f36).
