## Scope

Subset each served WOFF2 face to the code points the player-string data uses, derived at build time, so the art build check fails when strings change without a rebuild. A Tech test asserts every player-visible string's code points are in each served face.

## Criteria

- Each served face covers every player-visible code point.
- The art build check fails when strings and faces disagree.

## Decisions

- Art owns the subset build; Tech owns the coverage test in src/.
- The user chose to serve the subsets under a new family name, Chibi Sans, at `public/art/fonts/chibi-sans/ChibiSans-Regular.woff2` (400) and `ChibiSans-Bold.woff2` (700), with `OFL.txt` beside them; `public/art/fonts/liberation/` is removed.
- A subset is a SIL OFL 1.1 Modified Version, so it must not use the Reserved Font Names the sources declare (Arimo, Cousine, Liberation and Tinos). art-kit's `subsetWoff2` replaces name IDs 1, 3, 4 and 6 and rejects a reserved name in IDs 1 to 6; the copyright (0) and licence (13, 14) records are kept.
- Each face keeps `playerCodePoints()` from `src/ui/chrome/uiFontCodePoints.ts` plus printable ASCII (U+0020 to U+007E). `fonts.ts` imports that module, so the build and the coverage test share one code-point source.
- HarfBuzz's default layout features are kept: kerning ships in GPOS, and the legacy `kern` table is dropped.
- Tech moves `UI_FONT_RESOURCES`, the crash `theme.css` URLs, the font-family declarations and the shipped licence path to Chibi Sans in a stacked change.

## Outcome

Done in Art: both faces map all 96 kept code points, and together they shrink from 295,648 to 27,336 bytes (Regular 147,036 to 13,892; Bold 148,612 to 13,444). The served UI switches to them when Tech's stacked change lands.
