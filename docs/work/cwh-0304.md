## Decisions

- D1 (user, 2026-11-25): Go straight to 0.74; keep shipping the decoded archive copies.

## Scope

Adopt the published Game Kit release. Grouped builds ship gzip group archives, which the site
deploys and serves, and grouped installs decode them in the browser.

## Criteria

- The deployed site serves the compressed group files, and a grouped first install and update
  fetch them.
- A browser without the needed decoding support shows the shared startup error.
- Offline play, update reuse from 0.72 and save continuity still work.

## Outcome

The 0.74 build emits 39 files: the 35 of a 0.72 build and one gzip archive per update group.
A first install fetches the four gzip archives, 696,112 bytes, where the 0.72 build fetched
four decoded archives, 2,376,420 bytes (71% less). The decoded copies, still shipped, total
2,379,105 bytes.

| Group    | Decoded bytes | Gzip bytes |
| -------- | ------------- | ---------- |
| engine   | 1,117,116     | 283,087    |
| game     | 748,321       | 204,536    |
| game-art | 192,222       | 90,661     |
| shell    | 321,446       | 117,828    |

The engine and game-art groups keep their 0.72 digests. A page on 0.72 stages the update from
the decoded copies: it fetched the two changed archives (1,069,767 bytes), reused the two
unchanged groups (1,309,338 bytes), and the save was byte-identical after Update now. A
browser without `DecompressionStream` shows the kit's actionless unsupported-browser error
and starts no install, game or save write. The site serves `/.game-kit/group-*.bin` as
`application/octet-stream` with `no-transform`. The kit pin changed the certified lists'
proofs headers and arena hashes; their entries and the City approach evidence are unchanged.
