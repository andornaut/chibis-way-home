## Scope

Each timed hazard keeps one transition budget for a whole tick, shared by every object that
queries it that tick, so earlier far queries can make a later near query answer "unknown". Each
query gets its own budget, so an answer depends only on what was asked.

The support sampler handed to the encounter step has no order dependence: evaluating it eagerly
changes no output and only costs more, contrary to the cwh-0308 outcome. It stays lazy for cost.

## Criteria

- A timed hazard query answers the same regardless of how many queries ran before it in a tick.
- Recorded behaviour changes only where the shared budget ran out, measured before the change.

## Outcome

A query is charged the transitions it would take advancing from the snapshot, against its own
budget, so checkpoints left by earlier queries save work without changing which queries fit.
Before the change, the boss pin set (every `src/rules` test, the behaviour traces, the boss
simulator, properties and dodges, the evade tests and pair certification: 97 files, 2655 tests)
created timed hazard samplers only in `src/rules/boss/timedHazard.test.ts`: 15 queries, one of
which ran out of the shared budget, the deliberate exhaustion case, which answers the same with
its own budget. No other query's answer would differ, so no recorded trace, ability or effect
hash, certified list or arena hash changed, and none was refreshed.
